# Обсудить, спроектировать и добавить новую главу

1. Создать папку черновика:

   ```sh
   python3 scripts/new-level.py moon-reservoir --title 'Лунный водоём'
   ```

   Это создаёт `design.md`, `level.json` и `preview.svg` рядом с существующими главами. В кампанию черновик автоматически не включается.

2. Обсудить `design.md`: чем отличается глава, какие умения нужны, основной и секретный маршруты, обучение механике, бои, награды и условия приёмки. Изменять сюжет действующих глав для этого не требуется.

3. Отредактировать `level.json`. Карта — строки одинаковой длины: `.` пустота, `#` твёрдая стена, `=` односторонняя платформа. `interiors` использует `i` для внутренних помещений. Координаты объектов — мировые пиксели, один тайл равен 36. `cacheWalls.column/row` — индексы тайлов. У checkpoint `floorY` — высота пола, герой появляется на 42 пикселя выше него.

4. Выбрать существующие правила целей: `flight_ring`, `perch`, `cargo`, `ordered_key`, `crystal`, `mirror`, `obelisk`, `captain`, `speed_gate`, `rescue_console`. Разные правила можно комбинировать в `mission.nodes`; условия задаются поведением узлов, а не номером главы. `mission.kind` задаёт режим и подсказки. Для спокойного исследования подходят `explore`, пустой список узлов и открытый выход. Для реле используется `ordered_relays` и соответствующие объекты.

   `mission.parameters` позволяет менять `holdSeconds`, `minSpeed`, `calmSeconds`, `stormSeconds`, `cartStartX`, `cartFloorY`, `cartSpeed`, `escortRadius`. Для сопровождения нужен один узел `cargo`, расположенный правее начальной позиции груза. `requiresFlight` обязателен для воздушных колец. У врага-капитана поле `objective` содержит строковый ID его цели.

5. После согласования включить стабильный ID в список `levels/campaign.json`. Для сразу включаемого технического черновика есть явный флаг `--append`; для обсуждения лучше оставить главу вне списка.

6. Проверить:

   ```sh
   python3 tools/level_content.py --preview-dir build/level-previews
   ./scripts/check-game.sh
   ./scripts/package-apk.sh --local
   ```

   Проверка связности гарантирует путь по свободным клеткам для тела, но не заменяет ручную проверку высоты прыжков и запаса полёта. Пройти основной маршрут без отладочных наград, проверить каждую цель, секрет, возврат из подземелья и продолжение после закрытия приложения.

7. Не переименовывать опубликованные ID глав и объектов без миграции. При изменении геометрии или смысла checkpoint повысить `revision`. При перестановке глав сохранять ID. Старые индексы в `LegacySaveIds` не редактировать.

Чтобы ввести новую механику, добавить отдельный обработчик `ObjectiveRules.Rule`, зарегистрировать новый тип и его отображение в валидаторе. Если нужны новые события симуляции — добавить явный интерфейс события, а не проверку `levelIndex == ...`. Старые JSON-файлы и обработчики должны продолжить проходить эталонные тесты.

Для проверки самого процесса расширения есть `./scripts/check-level-extension.sh`: он временно добавляет тринадцатую главу, запускает полный прогон на эмуляторе и восстанавливает исходный каталог при завершении.
